## 1. 이 프로젝트가 무엇인가

Real Korea는 서울·수도권을 찾는 **영어권 방문자를 위한 로컬 데스크 매거진**입니다. 관광청식 공식 정보가 아니라 현지인이 친구에게 실제로 해줄 말을 다룹니다.

브랜드 약속은 `Local answers. Not the brochure.` 입니다.

구조는 Time Out식 시각·IA 스킨 위에 **Q&A 주도 블로그**를 올린 형태입니다. 랭킹 리스트("Best 50")는 콘텐츠 타입으로 존재하지 않습니다.

### 확정된 제품 규칙

```text
브랜드        Real Korea  (RealKO 아님, Grok-Bot 문서의 옛 이름)
언어          영어만. i18n 스키마는 en 하나로 준비, 전환 버튼 없음
지역          서울 + 수도권
계정          없음. 질문·댓글은 이름 + 이메일. 이메일 비공개
발행 권한     에디터만. 방문자는 질문과 댓글만
내비게이션    Ask a Local → Tips → Eat & Drink → Places → Shop (순서 고정)
수익화        제휴 + Shop 파트너 + 후원. v1 애드센스 금지
신뢰 표시     크림슨 Verified 체크 + lastVerifiedAt 날짜
```

### ⚠️ 이 Next.js 버전 주의사항

`site/AGENTS.md`는 `next dev`가 자동 생성·갱신합니다. 지우지 말고 그대로 두십시오. 이 버전은 학습 데이터와 다를 수 있으니 **`site/node_modules/next/dist/docs/`의 번들 문서를 기준으로** 작업하십시오.

확인된 규약은 다음과 같습니다.

- `PageProps<'/route'>`, `LayoutProps<'/route'>` 전역 타입 헬퍼 사용 가능 (`next dev`/`build`/`typegen` 시 생성)
- `params`, `searchParams`는 Promise. `await` 필요
- 404는 `app/not-found.tsx`
- Turbopack이 기본이라 `--turbopack` 플래그 불필요

**라우트를 삭제하면 `npx next typegen`을 실행하십시오.** 생성된 타입에 삭제된 경로가 남아 `typecheck`가 깨집니다. 실제로 겪은 문제입니다.

### 실행 및 검증

```powershell
cd D:\Project\RealKorea\site
npm install
npm run dev          # 3000 사용 중이면 자동으로 3001
```

```powershell
npm run lint
npm run typecheck
npm run build
```

세 명령 모두 현재 통과합니다. 빌드는 47개 페이지를 생성합니다.

**빌드에 경고 하나가 남아 있습니다.** `metadataBase`가 없어 Next가 OG 이미지 주소를 `localhost:3000`으로 대체한다는 내용입니다. 도메인 미확정 때문에 의도적으로 비워둔 것이며, `NEXT_PUBLIC_SITE_URL`을 설정하면 사라집니다.

**PowerShell 함정** — `npm run build 2>&1`을 쓰면 stderr 경고 때문에 종료 코드가 1로 보입니다. 빌드 실패가 아닙니다. `cmd /c "npm run build"`로 확인하거나 출력 리다이렉트를 쓰지 마십시오.

## 6. 반드시 지켜야 할 아키텍처 불변 조건

### 6-1. `lib/cms.ts`가 유일한 데이터 경계

```text
src/lib/cms.ts                  단일 TODO(CMS) 경계. 모든 조회·쓰기
src/lib/content/types.ts        PRD 03 스키마의 TypeScript 정의
src/lib/content/seed/*.ts       샘플 시드 데이터
src/lib/content/demo-queue.ts   런타임 제출 임시 저장
```

**`cms.ts` 외부에서 `content/seed`나 `demo-queue`를 import하지 마십시오.** Sanity로 교체할 때 이 한 파일만 고치면 되도록 설계했습니다. 모든 접근자가 이미 `async`인 이유도 이것입니다.

### 6-2. 이메일은 공개 타입에 존재할 수 없다 (FR-011, FR-020)

`Question`과 `Comment`는 에디터용이라 이메일을 갖지만, `PublicQuestion`과 `PublicComment`는 **구조적으로 그 필드를 가질 수 없습니다.**

변환은 `toPublicQuestion` / `toPublicComment` 한 곳만 지나가고, 스프레드 후 삭제가 아니라 **명시적 허용 목록**으로 구현했습니다. 비공개 필드가 새로 추가돼도 자동으로 새어나가지 않습니다.

라우트나 API에서 이메일을 직접 다루지 마십시오.

### 6-3. 샘플 데이터는 신뢰 지표를 가질 수 없다

`src/lib/content/seed/index.ts`의 `assertSamplesCarryNoTrustSignal`이 모듈 로드 시 실행됩니다. 샘플 문서가 `editorVerified`, `answerVerified`, `lastVerifiedAt`, 발행일을 가지면 **빌드가 실패합니다.**

실제로 위반 상태를 만들어 빌드가 막히는 것을 확인했습니다. 이 가드를 우회하지 마십시오. Verified 체크와 검증 날짜가 이 제품의 상품이기 때문입니다.

### 6-4. 색인은 `sample` 플래그가 제어

문서의 `sample`이 `true`면 `robots: noindex`가 붙고 sitemap과 JSON-LD에서도 빠집니다. 실제 콘텐츠로 교체되면 자동으로 색인됩니다. 수동으로 손댈 곳이 없습니다.

### 6-5. 그 외 규칙

- 폼은 POST 후 리다이렉트합니다. JS 없이 동작해야 합니다 (NFR-010)
- 확인되지 않은 값은 `Unknown`으로 표시합니다. 더미 `N/A` 금지 (FR-040)
- 지도는 `geo`가 있을 때만, API 키가 있을 때만 iframe을 냅니다
- `Hide traps`는 확정 트랩만 제외합니다. `"unknown"`은 함정이 아닙니다
- 날짜 포맷터는 로케일과 시간대를 고정했습니다 (`lib/format.ts`). 하이드레이션 드리프트 방지
- `lib/checklist.ts`는 `useSyncExternalStore`용 외부 스토어입니다. effect 내 setState를 피하기 위한 구조이니 되돌리지 마십시오

## 11. PRD 내부 불일치 (사용자 확인 필요)

구현 중 발견한 것들이며 임의로 결정하지 않고 보존했습니다.

**토픽 열거값 차이** — Tip 토픽은 `arrival|transit|money|etiquette|survival|seasonal`인데 PRD 02 §3.3의 Ask 칩은 `Money, Transit, Food, Etiquette, Survival, Other`입니다. `Food`와 `Other`가 Tip에 없습니다. `TipTopic`과 `QuestionTopic`을 별도 유니온으로 뒀습니다.

**댓글 부모** — PRD 03 §3.5는 `parentQuestion` 하나인데 FR-020은 Question·Tip·Place·Guide 4개 타입 요구입니다. 요구사항이 더 넓으므로 `CommentTarget`으로 일반화했습니다.

**Places 태그 필터** — PRD 02 §3.7은 `market, cafe, walk, shop-editorial`로 필터하라고 하는데 PRD 03 §3.2 스키마에 태그 필드가 없습니다. `walk`와 `shop-editorial`은 `vertical` 값이지만 `market`, `cafe`는 어디에도 없습니다. `vertical`로 대체했습니다.

**PRD 06 §3 미충족** — "desk strip에 Verified 질문 최소 1개"를 의도적으로 충족하지 않았습니다. 공식 답변은 사실 주장이고 Verified는 신뢰 표시라서 빌드가 만들어낼 수 없습니다.

## 12. 디자인 진행 상황 (현재 열려 있는 논의)

**여기가 다음 플랫폼이 이어받아야 할 실제 지점입니다.**

### 방식

`/design` 경로에 **클릭 가능한 실제 시안**을 만들어 비교합니다. AI 목업 이미지를 쓰지 않는 이유는 `docs/prd/design-mockups/v2/NOTES.md`에 기록된 대로 이미지 모델이 타이포를 계속 망치기 때문입니다(`KORF A`, `YIPS` 등). 사용자가 이 방식을 명시적으로 선호했습니다.

```text
src/app/design/layout.tsx    상단 고정 비교 바, noindex
src/app/design/page.tsx      시안 목록
src/app/design/shared.ts     공용 데이터 로더, 내비, 패널 순서
src/app/design/type.css      시안별 타이포·색 규칙
src/app/design/fonts.ts      Playfair Display + Archivo
src/app/design/jogakbo/      최대 강도
src/app/design/saekdong/     절제 버전
```

`/design`은 `robots.txt`에서 차단하고 `noindex`입니다. 방향이 확정되면 **폴더 전체를 삭제하고** 선택된 규칙만 `globals.css`로 옮깁니다.

### 지금까지의 이력

**1차** — A(Broadsheet 신문형), B(Gallery 인쇄 계간지), C(Desk 잉크 배경). 사용자가 C를 골랐다가 **철회**했습니다.

**2차** — 레퍼런스 10개 제시. 사용자 선호는 다음 순서였습니다.

```text
1위  Monocle          정돈된 그리드, 넓은 여백
2위  Hell Gate        단일 도시, 독자 후원, 꾸미지 않은 개성
3위  Defector         잉크 절제, 크롬에 강조색 없음
비선호  Rest of World  "첫 페이지가 난잡해 보인다"
```

이후 Monocle과 Rest of World 둘 다 디자인이 좋았다고 재평가했고, **"카드에 사진이 들어간 글 설명이 더 흡입력 있다"**는 점을 스스로 발견했습니다.

**3차** — D(Dancheong). 오방색을 카테고리 코드로 쓰고 창호·단청·한지를 구조로 넣었습니다. 사용자 평가는 **"오방색이 포인트가 없다, 확 와닿지 않는다, 기존 디자인에 단청만 하나 추가된 것 같다"**였습니다. 원인은 색이 칩 크기로만 들어가 면적을 차지하지 못한 것입니다.

**4차 (현재)** — A~D 전부 삭제. 사용자 요청은 **"아예 다른 컨셉, 한국적 색채가 강한 마치 필 더 코리아 같은 강렬한 한국색, 한국적이면서도 세련된"**입니다.

두 시안을 만들었습니다.

- **Jogakbo** — 최대 강도. 섹션 전체가 채도 높은 색 면입니다. 커버는 적색 판, 도착 가이드는 청록 판, Eat은 황금 판, 동네 그리드는 실제 조각보 패치워크입니다.
- **Saekdong** — 같은 팔레트를 절제. 종이 바탕에 색동 띠와 세로 레일, 금색 규칙선으로 색이 구두점 역할만 합니다.

**사용자가 아직 두 시안을 보고 평가하지 않았습니다.** 다음 플랫폼의 첫 작업은 이 평가를 받는 것입니다.

### 팔레트와 근거

```text
--k-red    #C8102E   적
--k-blue   #0E5C4E   청 (청록)
--k-gold   #EFB700   황
--k-azure  #1E5FA8   벽 (간색)
--k-ink    #14110F   흑
--k-paper  #F7F4EC   백
```

기존 크림슨 `#B43A3A`는 채도가 낮은 벽돌색이라 약해 보였습니다. 강해 보이는 레퍼런스는 채도 높은 적색을 작은 면적에 확실히 박습니다.

**대비 검증 결과이며 CSS로 강제했습니다.**

```text
흰 글자 / --k-red     약 5.9:1   AA 통과
흰 글자 / --k-blue    약 7.5:1   AA 통과
흰 글자 / --k-azure   약 5.5:1   AA 통과
먹 글자 / --k-gold    약 11:1    AA 통과
흰 글자 / --k-gold    약 1.9:1   실패 — 황색에는 항상 먹 글자
```

패널 클래스가 배경색과 글자색을 함께 정의하므로 대비 실패 조합을 **표현할 수 없습니다.**

### 전통을 다루는 원칙

PRD 04 §7이 한복 아이콘, 남산타워, 붓글씨, 태극 배경을 금지합니다. 기념품 가게처럼 보이기 때문입니다. 그래서 장식이 아니라 **구조**로 넣었습니다.

```text
조각보  큰 비대칭 색 면 + 보이는 이음선 → 페이지 레이아웃
색동    다섯 색 반복 띠 → 페이지 서명, 상하 각 1회
창호    두 줄 규칙선 + 세로 눈금 → 구분선 체계 (D안에서 사용)
한지    3.5% 불투명도 교차 섬유 결 → 종이 바탕
```

### ⚠️ PRD 위반 사항

**PRD 04 §2는 강조색을 크림슨 하나로 못 박고 넓은 면적 채색을 금지합니다.** 현재 두 시안은 이를 위반합니다. 이 방향으로 확정되면 **PRD 04를 개정하십시오.** 조용히 무시하면 나중에 정본과 코드가 갈라집니다.

## 16. 실제로 고친 버그 (재발 방지)

**질문 제출이 피드에 나타나지 않던 문제** — 라우트 핸들러와 페이지 렌더가 서로 다른 서버 번들로 컴파일되어 모듈 레벨 배열이 공유되지 않았습니다. `demo-queue.ts`의 저장소를 `globalThis`에 붙여 해결했습니다. 파일 주석에 이유를 남겨뒀으니 되돌리지 마십시오.

**effect 내 setState 린트 오류** — 두 번 발생했습니다. 마스트헤드 드로어는 렌더 중 상태 조정 패턴으로, 체크리스트는 `useSyncExternalStore`로 해결했습니다.

**삭제된 라우트의 생성 타입 잔존** — `npx next typegen`으로 해결합니다.

## 17. 설치돼 있지만 사용하지 않는 것

```text
src/components/magicui/blur-fade.tsx            Magic UI
src/components/motion-primitives/in-view.tsx    Motion Primitives
src/components/react-bits/blur-text.tsx         React Bits
```

세 애니메이션 라이브러리가 설치돼 있으나 현재 빌드에서 쓰지 않습니다. 사용자가 나중에 검토하겠다고 해서 보존한 상태입니다.

React Bits의 `BlurText`를 H1에 쓰는 것은 의도적으로 보류했습니다. 페이지에서 가장 큰 텍스트를 애니메이션하면 LCP와 CLS(NFR-001, NFR-002)와 충돌합니다. 적용하려면 사용자 지시를 받고 재측정하십시오.

모션 상한은 PRD 04 §6입니다. 호버·버튼 180ms, 커버 자동 줌 금지, 체크리스트 120ms 페이드, 컨페티 금지. `MotionProvider`가 `reducedMotion="user"`를 설정하고 `globals.css`도 `prefers-reduced-motion`을 처리합니다.

## 18. 한 문단 요약

Real Korea는 서울·수도권 영어권 방문자를 위한 에디터 발행 로컬 데스크 사이트입니다. PRD 06의 Turn A~G가 모두 구현돼 lint·typecheck·build 3종을 통과하며 47개 페이지를 생성합니다. 콘텐츠 계층은 `lib/cms.ts` 한 파일 뒤에 격리돼 Sanity로 교체할 준비가 돼 있고, 이메일 비공개와 신뢰 지표 위조 방지는 타입과 빌드 가드로 강제됩니다. 시드 데이터는 사실 주장을 의도적으로 비워 뒀습니다. **현재 열려 있는 작업은 디자인 방향 확정이며, `/design`의 Jogakbo와 Saekdong 두 시안이 사용자 평가를 기다리고 있습니다.** 확정 후에는 CMS 연결과 실제 콘텐츠 작성이 남습니다.
