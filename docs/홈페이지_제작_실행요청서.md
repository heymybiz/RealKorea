# Real Korea 홈페이지 제작 실행 요청서

이 문서는 Real Korea 홈페이지 구현 작업을 시작하거나 이어갈 때 Kiro에 전달하는 재사용 가능한 작업 지시서입니다.

정본은 `docs/prd/`의 **RK-PRD-1.0**입니다. 이 요청서와 PRD가 충돌하면 **PRD를 따릅니다.**

## 바로 복사할 실행 명령

```text
#File docs/홈페이지_제작_실행요청서.md
이 파일을 작업 지시서로 사용해서 Real Korea 구현을 이어가줘. docs/prd의 PRD 01~07과 site/README.md를 먼저 읽고, 현재 site/ 코드 상태를 점검한 다음 다음 단계를 구현·검증·보고해줘.
```

특정 단계만 진행할 때는 뒤에 범위를 덧붙입니다.

```text
PRD 06의 Turn D 범위만 진행해줘. Tips 인덱스와 상세, Place 상세의 팩트 스택까지.
```

## 에이전트 실행 지시

### 1. 정본과 읽는 순서

```text
docs/prd/README.md
docs/prd/01-PRD.md            비전, 사용자, 범위, 스택
docs/prd/02-IA-AND-PAGES.md   사이트맵, URL, 화면 스펙, 상태
docs/prd/03-CONTENT-AND-CMS.md 콘텐츠 타입, 필드, 보이스
docs/prd/04-DESIGN-SYSTEM.md  토큰, 컴포넌트 (목업보다 우선)
docs/prd/05-REQUIREMENTS.md   FR/NFR 수용 기준
docs/prd/06-VIBE-CODING.md    구현 순서와 완료 정의
docs/prd/07-KO-APPENDIX.md    한국어 해설 (참고용)
site/README.md                설치된 기술 기반과 컴포넌트 사용법
```

우선순위는 다음과 같습니다.

```text
PRD 01~06  >  04 토큰  >  목업 JPEG  >  Grok-Bot 폴더
```

`Grok-Bot/`의 기존 기획 문서는 **배경 자료**입니다. PRD와 다른 내용(RealKO 브랜드명, 7개 카테고리 메뉴, 애드센스 중심 수익화)은 반영하지 않습니다.

### 2. 목업 사용 규칙

목업은 `docs/prd/design-mockups/v2/`가 현행이고 v1과 v0.1은 동결입니다. 무드만 참고하고 JPEG 안의 문자는 신뢰하지 않습니다. 실제로 확인된 목업 오류는 다음과 같으며 절대 구현하지 않습니다.

- 헤더의 `TIME OUT × MONOCLE` 주석
- `DESTINATIONS / EXPERIENCES / PLANNING / MAGAZINE / GUIDES / NEIGHBORHOODS / PRACTICAL / ABOUT` 같은 잘못된 내비게이션
- 목업 본문에 렌더링된 스펙 설명문
- 한글 주 헤드라인, 별점, Write a review
- 회색 Verified 실드 (크림슨 체크가 정답)
- 서로 모순되는 교통 정보 (동대문역 1호선 대 상왕십리역 2호선)

### 3. 작업 위치와 보호 범위

- 구현은 `site/` 안에서만 진행합니다.
- `docs/`와 `Grok-Bot/` 문서는 사용자가 명시적으로 요청하지 않으면 수정하지 않습니다.
- 기존 `site/` 설정과 설치된 패키지를 먼저 확인하고 프로젝트를 다시 생성하지 않습니다.
- 새 패키지는 꼭 필요할 때만, 정확한 버전으로 추가하고 이유를 보고합니다.

### 4. 절대 금지 (PRD 06 §0, 05 FR)

- 로그인, 계정, OAuth, `Sign in` UI
- `adsbygoogle` 및 모든 디스플레이 광고
- `/map` 전용 지도 라우트
- 랭킹형 "Best 50" 콘텐츠 타입
- 언어 전환 버튼, 영어 외 UI
- 예약·항공·숙소 부킹 엔진
- 다크 모드 토글
- Place 페이지의 `Write a review` 주요 CTA
- Tip 본문 안의 제휴 상품 카드

### 5. 확정된 제품 규칙

```text
브랜드        Real Korea
언어          영어만 (i18n 스키마는 en 하나로 준비, 전환 없음)
지역          서울 + 수도권
계정          없음. 질문·댓글은 이름 + 이메일 (이메일 비공개)
발행          에디터만. 방문자는 질문과 댓글
내비게이션    Ask a Local → Tips → Eat & Drink → Places → Shop (순서 고정)
수익화        제휴 + Shop 파트너 + 후원. v1 애드센스 없음
신뢰 표시     크림슨 Verified 체크 + lastVerifiedAt
```

### 6. 카피 규칙

PRD 06 §4의 카피 덱과 02의 헤드라인·플레이스홀더는 **확정 문장**입니다. 더 친근하게 고치지 않고 그대로 사용합니다.

로마자 표기는 첫 등장만 `English Name (한글)`이고 이후는 영어만 씁니다. 제목을 한글로 시작하지 않습니다.

### 7. 디자인 토큰

```text
paper       #F4EFE6
paper-warm  #EFE6D6
ink         #161513
ink-soft    #5C574E
rule        #D9D1C3
crimson     #B43A3A
crimson-dark #8E2C2C
```

강조색은 크림슨 하나뿐이며 넓은 면적을 채우지 않습니다. 최대 콘텐츠 폭 1120px, 카드 라운드 최대 16px, 버튼 4px입니다.

### 8. 모션 정책

1차 기준은 PRD 04 §6입니다.

- 호버 밑줄과 버튼은 180ms ease-out
- 커버 이미지 자동 줌 금지
- 체크리스트는 즉시 반응 + 120ms 페이드, 컨페티 금지
- `prefers-reduced-motion` 준수

설치된 Magic UI, Motion Primitives, React Bits는 위 기준을 넘지 않는 범위에서만 사용합니다. React Bits의 H1 텍스트 애니메이션은 **사용자가 별도로 지시할 때만** 적용하고, 그때 LCP와 CLS를 다시 측정해 보고합니다.

### 9. 콘텐츠 원칙

- 실제 확인되지 않은 요금, 운영시간, 통계, 교통 정보를 만들어 넣지 않습니다.
- 시드 콘텐츠는 명백한 샘플로 표시하고 사실 주장은 비웁니다.
- 실제 사진이 없으면 플레이스홀더를 쓰고 AI 생성 이미지를 실제 장소 사진처럼 쓰지 않습니다.
- 의료·법률 지시형 문구를 쓰지 않습니다.

### 10. 구현 순서

PRD 06 §2의 Turn A~G를 따릅니다.

```text
A  기반: 토큰, 폰트, Masthead, Footer, 전체 라우트
B  홈: 커버, 검색, 데스크 스트립, First 24h 체크리스트
C  콘텐츠 계층: 03 스키마 (CMS 미연결 시 시드 데이터 허용)
D  Tips, Places, 팩트 스택, 지도 임베드
E  Ask a Local, 댓글, 허니팟, 레이트 리밋, noindex
F  Eat, Shop, Guide, About, 법적 페이지
G  검색, SEO, 접근성, 404, QA
```

CMS는 시드 데이터로 먼저 만들고 Sanity 연결은 별도 단계로 둡니다. `TODO(CMS)` 경계는 한 파일에만 둡니다.

### 11. 검증

각 단계 종료 시 `site/`에서 다음을 실행하고 모두 통과시킵니다.

```powershell
npm run lint
npm run typecheck
npm run build
```

개발 서버는 장시간 실행하지 않고 사용자가 직접 확인할 명령만 안내합니다.

### 12. 완료 보고

- 구현한 화면과 기능, 대응하는 PRD FR/NFR 번호
- 생성하거나 변경한 파일
- 검증 결과
- 사실 정보나 사진이 없어 비워둔 항목
- 사용자 결정이 필요한 남은 항목

## 아직 사용자 결정이 남은 항목

개발 블로커는 아니지만 출시 전에 필요합니다.

- 도메인 (PRD 11: `realkorea.com` 등 미확정) → `metadataBase`와 절대 canonical
- Google Maps 키 또는 Mapbox 전환
- 후원 결제 수단
- 에디터 알림 이메일 (Resend 또는 Postmark)
- 분석 도구 (Plausible 또는 GA4)
- 레이트 리밋 저장소 (서버리스에서는 외부 저장소 필요)
- 사진 라이선스
